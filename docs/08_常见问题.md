# 08：常见问题

## 为什么 `doctor` 显示模型配置未就绪？

复制 `.env.example` 为 `.env`，填写 `OPENAI_API_KEY` 和 `OPENAI_MODEL`。
自建或第三方兼容接口还要填写 `OPENAI_BASE_URL`。`doctor` 不会真正请求模型。

## 为什么基础示例没有调用 LLM？

状态、边、reducer、Send、检查点、Store、interrupt 和 streaming 都是 LangGraph 运行时
能力，不应通过模型输出掩盖其行为。先用确定性节点理解框架，再进入 ReAct。

## 单元测试里的模拟模型是否违反“只用真实模型”？

不违反。CLI 和综合助手运行时没有离线兜底，只调用真实兼容模型。模拟模型只在测试中
注入，用于验证工具循环和路由，不产生费用，也不会因网络波动让单元测试随机失败。

## 为什么模型没有调用计算器？

确认模型支持 tools/function calling。尝试明确提示“请调用计算器工具”。某些推理模型、
旧模型或兼容网关虽然能聊天，但不实现标准 tool_calls。

## 为什么 messages 流不是逐字输出？

模型和网关必须支持流式传输。有些兼容网关会把完整消息一次返回。可以同时观察
`updates`，确认图仍按节点执行。

## 为什么 interrupt 后 invoke 的返回值没有明显问题字段？

0.3.34 的不同调用模式对 interrupt 事件展示略有差异。可靠做法是读取：

```python
snapshot = graph.get_state(config)
print(snapshot.next)
print(snapshot.tasks)
```

只要 `next` 非空且指向审核节点，图仍处于暂停状态。

## 为什么同一用户换 thread 后仍记得上次内容？

这是 Store 的预期行为。checkpointer 按 thread_id 隔离短期状态；Store 示例按 user_id
命名空间保存长期档案。

## 为什么重启程序后记忆消失？

示例使用 `MemorySaver` 和 `InMemoryStore`。两者只存在于当前 Python 进程。需要跨重启
保存时，换用持久化实现并配置数据库。

## 并行结果为什么顺序变化？

并行任务完成顺序不保证等于派发顺序。示例汇总时排序。生产代码可携带原始 index、
优先级或依赖信息后显式排序。

## 为什么达到 recursion limit？

通常是条件边没有退出、ReAct 模型反复调用工具，或“修订计划—人工审核”循环次数过多。
先检查路由状态，再合理提高调用配置中的 `recursion_limit`；不要只无限增大限制。

## 可以直接把参考工程全部 requirements 复制过来吗？

不建议。参考工程包含数据库、对象存储、Autogen、企业内部 API 等大量业务依赖。本教程
只固定实际需要的 LangGraph/LangChain 子集，减少冲突和安装时间。

## `.env` 可以提交吗？

不可以。`.env` 已加入 `.gitignore`。只提交不含真实值的 `.env.example`。如果密钥曾
进入 Git 历史，应立即吊销并重新生成，仅删除当前文件不够。
