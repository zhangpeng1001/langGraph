# 数据中台治理图学习项目

`src/data_platform` 是一个使用本地 Mock 数据任务、MongoDB 持久化检查点的
LangGraph 学习示例，按照 `graph_optimize_codex.md` 的建议把数据治理流程拆成
可审计的状态机。

## 启动

先复制 `.env.example` 为 `.env`，并将 `MONGODB_URI` 替换为已授权的实际连接串；
不要将密码提交到 Git。数据中台流程会在 `potato_data_platform` 数据库的
`langgraph_checkpoints` 和 `langgraph_checkpoint_writes` 集合中保存检查点。

然后在项目根目录执行：

```powershell
pip install -e .
python -m data_platform
```

然后打开 <http://127.0.0.1:8003>。

也可以直接执行：

```powershell
uvicorn data_platform.api:app --host 127.0.0.1 --port 8003
```

## 如何学习这条链路

1. 输入治理请求并启动，图会在 `review_plan` 的 `interrupt` 暂停。
2. 点击“批准计划并继续”，后端用同一个 `thread_id` 发送 `Command(resume=...)`，从检查点恢复。
3. `execute_next` 通过幂等键创建 Mock 外部任务，`wait_external` 再次中断等待异步回调。
4. 点击成功/失败回调，后端先更新 Mock 任务，再恢复图；`resolve_external` 校验任务 ID、运行 ID 和终态。
5. “后台 2 秒后自动回调”使用 `asyncio.sleep` 创建真正的异步等待，等待期间 HTTP 服务仍能处理其他请求。

## 关键设计

- **检查点**：`MongoDBSaver` 以 `configurable.thread_id` 隔离每个治理运行。运行管理器通过确定性规则从 `run_id` 推导 thread_id，因此应用重启后，前端仍能用原 run_id 读取、审核或恢复挂起流程。
- **人工审核**：计划是显式结构化数据，审核拒绝不会启动外部任务；跳过质检等质量门禁也会显示在计划中并等待审核。
- **异步任务**：Mock 平台的 `start_task` 返回 `task_id`，按钮模拟回调；重复相同幂等键只返回原任务。
- **事实正确性**：任务失败进入 `FAILED`，不会继续入库；发布成功前不会显示服务地址或治理成功。
- **依赖边界**：没有真实 LLM、MQTT 或数据中台接口；采集、质检、清洗、入库和发布任务均为本地 Mock。唯一外部基础设施是 MongoDB，用于可靠保存 LangGraph 检查点。

## MongoDB 检查点与恢复

服务启动时会创建共享 `MongoClient`、执行 `ping` 并由 `MongoDBSaver` 初始化必要索引；
连接或鉴权失败会让服务在启动阶段失败，防止审核中断无法保存。审核 API 收到决定时：

1. 根据 `run_id` 推导 `thread_{run_id}`；
2. 从 MongoDB 读取该 thread 的最新 checkpoint；
3. 使用相同 config 执行 `Command(resume=...)`；
4. 将恢复后的状态再次写入 MongoDB。

这意味着服务重启不会丢失审核中的图状态。Mock 外部任务本身仍只存在当前进程；它用于
教学按钮演示，不应作为真实任务引擎实现。

## 推荐阅读顺序

先看 `domain.py` 的枚举和请求模型，再看 `graph.py` 的节点与边，最后看
`manager.py` 如何把 HTTP 动作映射为检查点恢复。前端 `static/app.js` 展示了
最小的 REST 交互方式。
